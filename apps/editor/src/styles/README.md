# Стили Constructor

`editor.ts` — единственный вход стилей для `app.ts`. Он задаёт порядок общей геометрии,
публичного CSS Framework и `editor.css`. Общие UI-функции не импортируют стили.
Framework остаётся отдельным CSS-модулем, чтобы сборщик переиспользовал его встроенные
шрифты между редактором и демо. Локальная последовательность `@import` задана в `editor.css`.

| Владелец      | Содержимое                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------- |
| `shell/`      | Шапка, галерея, секции навигации, рабочее пространство, подсказки и режимы панелей                |
| `canvas/`     | Авторское полотно, композиции, inline-редактирование, масштабируемые инструменты и размеры слайда |
| `inspector/`  | Поля, геометрия, оформление, настройки слайдов, сообщения и прокрутка панели                      |
| `dialogs/`    | Библиотеки, каталог, подбор оформления, материалы и лениво загружаемый ИИ                         |
| `responsive/` | Существующие адаптивные и печатные правила, сохраняющие своё место в каскаде                      |
| `shared/`     | Группы настроек и общая геометрия полей, используемые редактором и демо                           |

`shared.css` объединяет общую геометрию, `product.css` — стили продукта, необходимые также демо.
Демо имеет собственный вход `apps/editor/demo/styles.ts`; он не загружает всё рабочее пространство.
ИИ подключает только `dialogs/ai.css` при открытии панели. `documentation.css` вне этой папки
принадлежит генератору руководств. Автономный предпросмотр и HTML используют публичный CSS
Framework внутри iframe, без стилей оболочки.

## Порядок и границы

При переносе правил сохранены исходные селекторы, объявления и их последовательность.
Общая геометрия редактора исторически предшествует Framework, а основная оболочка следует
за ним; у демо общая геометрия подключается последней. Этот порядок теперь виден во входах,
а не зависит от обхода импортов TypeScript. Не переставляйте импорты по алфавиту.

Часть владельцев имеет несколько небольших файлов: например, `canvas/authoring.css`,
`canvas/compositions.css` и `canvas/controls.css` соответствуют разным позициям каскада.
Объединение таких файлов или перенос всех media queries в конец может изменить интерфейс.
Сначала проверьте пересечения селекторов и состояния в трёх браузерах. CSS `@layer` не
используется: помещение оболочки в слой при обычном CSS Framework изменило бы приоритеты.

Новые правила добавляйте к соответствующему владельцу. Публичные токены `--af-*` и визуальные
рецепты контролов принадлежат Framework. Локальные размеры интерфейса используют
`--constructor-*`. Для нового CSS-файла добавьте явный импорт во вход или его композицию.
Импорты CSS из TypeScript разрешены только в двух модулях входов и ленивой панели ИИ.
Проверка также требует, чтобы приложение подключало свой модуль входа ровно один раз.

`npm run check:ui` проверяет токены и контролы, владельцев входов, существование импортов,
циклы, повторное подключение в одном входе, поздние `@import` и недостижимые файлы.
Для регрессий запустите `editor-styles`, `gallery`, `ui-framework`, layout/followup/responsive,
controls-layout, settings-spacing, диалоги и `demo-diagnostics` в Chromium, Firefox и WebKit.
`editor-styles` также входит в приёмку Docker.

## Размер презентации

Экранное правило в `canvas/modes.css` резервирует рамку 16:9 до вызова ResizeObserver.
Высота ограничена 900 px, как у слайда 1600×900 публичного runtime. Это исключает обратную
связь при открытии инспектора в WebKit. Единственный новый `!important` намеренно заменяет
inline-высоту renderer; исключение относится только к размеру рамки на холсте редактора.
Правило не применяется к печати, iframe предпросмотра и экспорту. Масштаб содержимого
по-прежнему рассчитывает Framework. Обработчики ошибок браузера не подавляются.
