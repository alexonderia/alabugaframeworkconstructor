# Стандартная сетка из Figma

Источник: [Grid, 625:1830](https://www.figma.com/design/ObAoKiDwraibmQrxUNvGWI/Design-System?node-id=625-1830). Контекст и снимок получены 20 ноября 2026 года. Эталон сохранён в соседнем репозитории Framework: `design/figma/grid-2026-11-20/`; файлы зарегистрированы с SHA-256 в манифесте архива.

| Параметр | Значение |
| --- | --- |
| Холст презентации | 1920×1080 px |
| Колонки | 24 × 64 px |
| Строки слайда | 12 × 64 px |
| Между ячейками | 8 px |
| Поля слева / справа | 100 / 100 px |
| Поля сверху / снизу | 176 / 48 px |
| Область размещения | 1720×856 px |
| Адаптация сайта | По умолчанию 12 колонок на планшете и 4 на телефоне; высота растёт |

Адаптивные количества колонок и поля 32/20 px на узких экранах — решения веб-реализации. Исходный узел Figma задаёт настольную сетку. Количество адаптивных колонок можно изменить в настройках.

## Изменения Framework

Изменение библиотеки необходимо: версия 1.3.1 фиксировала холст 1600×900 и проверяла размещение в области высотой 688 px. Одной смены чисел в Constructor недостаточно для размещения 12 строк и одинакового HTML/PDF.

Изменения находятся в отдельном репозитории `../alabuga-framework`:

- Публичный модуль `@alabuga/framework/grid`: `standardGrid`, `gridFrame`, `gridRows`, `remapSectionGrid`.
- Схема 6 с необязательными `grid.frame` и `grid.responsive`. Без них сохраняются прежние геометрия и нормализация версий.
- Runtime и CSS учитывают холст, поля и адаптивные колонки; проверка переполнения использует фактическую область размещения. Печать получает размер страницы для каждого слайда.
- Варианты компоновки и подбор оформления сохраняют явно заданную сетку.
- Справочник и руководства RU/EN описывают контракт; раздел `#grid` показывает живой пример.

В Constructor подключён готовый архив `vendor/alabuga-framework-1.4.0-grid.0.tgz` с контрольной суммой в package-lock.json. Исходники библиотеки в Constructor не копируются. Это локальная предварительная сборка, публикация в npm-реестр не выполнялась. Dockerfile включает архив до `npm ci`.

## Поведение Constructor

Новые документы, все встроенные шаблоны и копии пользовательских композиций для каталога получают стандартную сетку. Сохранение в каталог не меняет сетку и ссылки исходного проекта. При вставке композиция наследует общую сетку текущего документа.

Общая сетка хранится в `templateInfo.documentGrid` и материализуется в `pages[].grid` для публичного рендера и экспорта. Изменение действует на все наследующие разделы и новые секции/слайды. Флажок «Своя сетка для этой секции/этого слайда» добавляет явное исключение в `templateInfo.gridOverrides`; снятие флажка возвращает раздел к общей сетке. Дублирование раздела сохраняет исключение. Устаревшие ссылки на удалённые разделы удаляются при проверке проекта.

При открытии проекта с явными полями первая сетка становится общей; прежние случайно разные сетки разделов приводятся к ней с пересчётом блоков. Старые файлы без полей читаются с прежней геометрией. Явное действие «Применить стандартную сетку» восстанавливает эталон для всех наследующих разделов, либо только для выбранного исключения. Проверка всех разделов выполняется до фиксации; ошибка в одном из них не оставляет частично применённых настроек. Изменение всей сетки отменяется одной операцией истории.

В «Привязка → Настроить сетку раздела» редактируются число колонок, высота строки, промежутки, четыре поля и адаптивные колонки сайта. Настройки сохраняются в JSON и IndexedDB, поддерживают Undo/Redo. Формат контейнера проекта и версия IndexedDB остаются 3; документ с новой сеткой требует читателя схемы 6.

Направляющие показывают колонки на всю высоту холста и строки на всю ширину, с теми же началом и промежутками, что в эталоне. Привязка, изменение размера и поиск свободного места используют границы фактической сетки. Preflight и автономный HTML используют новый публичный runtime. ИИ-черновики при вставке в документ с новой сеткой пересчитываются в её координаты.

Проверки `tests/standard-grid.spec.ts` измеряют размеры и поля в редакторе, автономном HTML и печати, проверяют адаптивные колонки, растущую высоту сайта, сохранение настроек, сброс и Undo. Библиотечные проверки покрывают последнюю ячейку слайда, отклонение выхода за границу, старые документы и преобразование всех композиций без потери данных.


## Редактирование заполненной сетки

Обычное применение новых колонок, строк, промежутков или полей использует `grid-change.ts`. Планировщик пересчитывает границы блоков, устраняет коллизии округления и при необходимости уплотняет слайд, соблюдая минимумы публичного реестра Framework. Для сайтов новые строки добавляются по мере необходимости. Содержимое и идентификаторы сохраняются; изменение проходит валидацию всего документа и применяется одной операцией EditorSession. При ошибке исходный документ не изменяется.

Сайт и презентация используют явную кнопку «Применить сетку» и отмену черновика. Ввод не вызывает промежуточных применений при переходе между полями. Ошибка показана рядом с параметрами и сохраняет черновик. Сброс к стандарту не требует предварительно применить ошибочные значения. Переходы, сохранение и закрытие настроек применяют корректный черновик и блокируются при ошибке. Заголовок секции сохраняется независимо от сетки.

Проверки `grid-change.test.ts` покрывают заполненные слайды, коллизии округления, минимумы компонентов, сайты, старую схему и Undo. `grid-settings.spec.ts` проверяет ввод с клавиатуры, явное применение, сохранение содержимого, ошибку с сохранением черновика, отмену, сброс, закрытие и перезагрузку отдельно для сайтов и презентаций.


## Экран и ширина рабочей области

Настольный холст сайта с явной сеткой сохраняет ширину `grid.frame.width`, независимо от панели инспектора. Уменьшение окна и масштаб меняют экранный размер холста, сохраняя логические размеры и колонки. Начальный показ вписывает холст, ручной масштаб остаётся под управлением пользователя. Адаптивные колонки включаются выбором экрана, а в автономном HTML — фактической шириной браузера.

`grid-viewport.spec.ts` воспроизводит шапку из встроенного корпоративного сайта с настройками 20/5/4. Проверяются фактические колонки, направляющие и позиции блоков с открытым инспектором, при 100%, после вписывания и сужения окна до 390 px. Переключение к прежнему проекту освобождает фиксированную ширину.
