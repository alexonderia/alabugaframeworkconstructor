# A5: организация CSS и размеры презентации

Дата: 17 ноября 2026 года. Продолжение [аудита архитектуры и UX](2026-11-13-architecture-ux.ru.md) после разделения сессии, представлений и хранилища.

## Изменения

У редактора один явный вход стилей: `apps/editor/src/styles/editor.ts`, задающий порядок общей геометрии, публичного CSS Framework и `editor.css`. Импорты из `ui.ts` удалены; общие UI-функции больше не влияют на порядок стилей. Правила разнесены по владельцам `shell`, `canvas`, `inspector`, `dialogs`, `responsive`, `shared`. Порядок задан во входах; названия `style.css` и `styles.css` для стилей редактора устранены.

Демо использует свой вход `apps/editor/demo/styles.ts`, сохраняя собственную геометрию страницы и общий интерфейс. Framework остаётся отдельным CSS-модулем для переиспользования встроенных шрифтов между двумя страницами в выпускной сборке. ИИ лениво загружает только `styles/dialogs/ai.css`. `documentation.css` остаётся входом генератора руководств. Предпросмотр и HTML используют автономный CSS Framework внутри iframe.

При переносе сохранены все селекторы, объявления и последовательность 425 верхнеуровневых правил/at-rules, включая прежнее положение media queries. У демо каскад также сохранён полностью. Это проверено сравнением PostCSS AST с копией исходных файлов. Небольшие отдельные файлы сохраняют прежнее место правил в каскаде; их объединение и сокращение старых `!important` требуют самостоятельной проверки пересечений, а не механической перестановки.

В `npm run check:ui` включена проверка владельцев CSS-входов: запрещены скрытые импорты из TypeScript, повторное подключение в одном входе, циклы, отсутствующие и недостижимые файлы, `@import` после правил. Отрицательные примеры проверяются в `tests/style-entries.test.mjs`. Порядок и правила расширения описаны в [README стилей](../../apps/editor/src/styles/README.md), команда проверки — в руководствах RU/EN.

Проверка выпускных HTML/CSS подтвердила общий файл Framework размером 514 861 байт с четырьмя `@font-face`; оба HTML ссылаются на него. В CSS редактора (38 989 байт) и демо (9 520 байт) этих шрифтов нет. Поэтому консолидация не заставляет повторно скачивать весь Framework при переходе между страницами. Имена файлов содержат хеш сборки и не являются контрактом.

## Исправление WebKit

Ранее в WebKit открытие инспектора презентации стабильно вызывало `ResizeObserver loop completed with undelivered notifications.` Ошибка воспроизводилась и до разделения хранилища: инспектор сужал полотно, а renderer изменял inline-высоту наблюдаемой рамки. Проверка перехода в галерею обнаруживала ошибку, накопившуюся при открытии инспектора.

Экранное правило `canvas/modes.css` резервирует рамку 16:9 с пределом 900 px, соответствующим неувеличенному слайду 1600×900. Framework продолжает масштабировать содержимое. Один новый `height: auto !important` исключает изменение фактической высоты из обработчика ResizeObserver. Правило ограничено холстом редактора и экранным носителем: печать, iframe и экспорт его не получают. Обработчики ошибок браузера не подавляются.

Рамка теперь имеет точное соотношение 16:9 по внешним границам; раньше inline-высота вычислялась по внутренней ширине. Разница при рамке в 1 px составляет около 1,13 px по высоте. Содержимое слайда не изменяется. Независимость названий секций и элементов, компактные однострочные поля и отсутствие дополнительного заголовка на полотне сохранены.
