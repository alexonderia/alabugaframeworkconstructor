# Данные и восстановление

Точное размещение использует схему документа 7 и Framework 1.4.0-grid.4: `position.free: true` разрешает дробные координаты и размеры, сохраняя общую систему единиц сетки. Публичный рендерер переводит их в точные размеры; автономный HTML и печать используют ту же геометрию. Свободные блоки могут пересекаться и размещаться в полях холста. Существующие целочисленные позиции и схемы 1–6 продолжают читаться. Формат оболочки проекта и версия IndexedDB остаются 3.

## Шаблоны и неразмещённые блоки

Constructor хранит идентификатор и версию шаблона в `templateInfo`. Проект содержит собственные секции, блоки и материалы. Для открытия достаточно файла проекта или записи IndexedDB. Сведения о старой версии шаблона сохраняются даже после обновления каталога.

Документы без `templateInfo` открываются с прежними правилами. Расширение совместимо с текущими схемами AFDocument и оболочками JSON версий 1–3 при чтении в Constructor. Редакции Constructor до этой итерации могут отклонить новый файл с `templateInfo`.

Отложенные блоки сохраняются вместе с проектом, материалами и ревизиями. Можно вернуть всю группу в новый раздел или разместить отдельный блок в существующей секции либо на слайде. Предпросмотр и HTML используют размещённые секции.

«Мои композиции» хранятся в локальном каталоге браузера. Переносимый файл коллекции имеет формат `alabuga-compositions`, версию 1 и включает встроенные локальные изображения. Максимальный размер файла — 100 МБ, число композиций — 100. Весь файл проходит проверку перед одной транзакцией записи. Импорт присваивает новые идентификаторы композициям. Вставленные экземпляры входят в переносимый проект.

## Где находятся проекты

IndexedDB `alabuga-workspace` хранит проекты, материалы, версии, настройки и краткие сведения для витрины. Хранилище принадлежит браузерному профилю и origin: схема, имя хоста и порт. `localhost` и `127.0.0.1`, порты 5173 и 4176 — разные места хранения. Контейнер не содержит эту базу.

Состояние «Сохранено» показывается после успешного завершения транзакции. Просмотр и миниатюры не обновляют дату проекта. При ошибке записи оставайтесь в редакторе, повторите сохранение или скачайте переносимый проект.

## Резервная копия

Сбой записи отменяет всю затронутую транзакцию. В частности, при ошибке сохранения описания загруженное изображение не остаётся отдельной незавершённой записью. Повтор загрузки создаёт обычный материал; ошибка не изменяет содержимое текущего проекта.

Скачивайте файл проекта через витрину или редактор. Он содержит документ и необходимые локальные материалы и пригоден для повторного редактирования. HTML — готовый результат, а не замена переносимому проекту. Внешние HTTP(S)-изображения остаются внешними; для независимости загрузите их в библиотеку до экспорта.

Перед сменой домена, порта, браузера, профиля или очисткой данных скачайте проекты. Откройте новый адрес и импортируйте файлы. Автоматического переноса между origin и синхронизации между устройствами нет.

## Версии и корзина

Сохраняется до 20 версий после паузы редактирования, при выходе и перед восстановлением или заменой. Версию можно создать вручную в меню проекта. При восстановлении текущая версия сохраняется. Корзина удерживает проект и историю; автоматической очистки нет. Окончательное удаление подтверждается отдельно и не удаляет общие материалы других проектов. Удалённый проект не появляется из автосохранения другой вкладки.

При конфликте двух вкладок устаревшая запись отклоняется целиком. Можно сохранить свои правки отдельным проектом или открыть сохранённую версию. Для очистки изображений используйте «Хранилище и материалы»: приложение показывает использование и повторно проверяет ссылки перед удалением.

## Совместимость

Документы с отдельными адаптивными размерами сохраняются в схеме 4 (Framework 1.2+). Без новых параметров схемы 1–3 по-прежнему нормализуются в 3; явно заданная схема 4 сохраняется. Старые версии Framework 1.1 не открывают схему 4. Версия переносимой оболочки проекта остаётся 3. IndexedDB обновляется до версии 3 с индексом истории по проекту. Миграции баз 1–2 сохраняют документы, материалы и версии. Старое локальное сохранение переносится однократно. При блокировке обновления базы закройте другие вкладки и повторите открытие.

## Отмена и аварийное восстановление

Отмена относится к текущей редакторской сессии; история версий и переносимый файл решают задачи долговременного восстановления. Черновик ИИ сохраняется отдельно и восстанавливается после перезагрузки. Не очищайте данные браузера для устранения ошибки до создания резервных копий. Для диагностики передавайте минимальный воспроизводимый проект без лишних данных.

## Совместимость после разделения

Имя БД alabuga-workspace и object stores сохраняются; версия 3 добавляет индекс revisions.project. Legacy-ключ alabuga.builder.document.v1 сохраняется. Поддерживаются схемы документа 1–5: прежние схемы 1–3 без новых параметров нормализуются в 3, схемы 4 и 5 сохраняют адаптивные размеры и настройки слайдов. Оболочки проектов 1–3 и без version поддерживаются; новая оболочка остаётся версии 3. Будущие версии и отсутствующие материалы отклоняются до записи. Массовая перезапись проектов при первом запуске не выполняется. Маркеры установленных коллекций, ревизии, корзина, tombstones и AI-черновики сохраняются. Внутренняя версия записи проекта не меняет формат AFDocument.

Настройки подписи и номера слайда (page.chrome, Framework 1.3+) используют схему документа 5; для повторного открытия нужен Framework 1.3 или новее. Проекты без этих настроек сохраняют прежнюю нормализацию в 3/4. Переносимая оболочка проекта и IndexedDB остаются версии 3. Цвет текста и фон номера требуют Framework 1.3.1 или новее.

Сетка с `grid.frame` и `grid.responsive` использует схему документа 6 и локальную сборку Framework 1.4.0-grid.0. Старые документы без этих полей не мигрируют на новую сетку при открытии. Контейнер файла проекта и IndexedDB остаются версии 3. Для открытия новых проектов нужен Framework с поддержкой схемы 6.

`templateInfo.documentGrid` хранит общую сетку; `templateInfo.gridOverrides` содержит идентификаторы разделов с собственной сеткой. Параметры материализуются в каждой `pages[].grid`, поэтому экспорт и публичный Framework получают готовую геометрию без метаданных Constructor. Изменение общей сетки проверяет все наследующие разделы до записи и отменяется одной операцией истории. Шаблоны каталога хранят стандартную сетку; вставленные экземпляры наследуют сетку документа.
