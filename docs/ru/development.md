# Разработка

## Чистая установка

Используйте Node.js 24.19.0 и npm 11.17.0. Настройте приватный scoped registry и read token, затем выполните npm ci. Все внутренние workspaces используют корневой package-lock.json. npm run dev готовит руководства и запускает Vite; Framework уже установлен готовым пакетом. Python нужен только отдельным сценариям отчётов.

## Команды

Модульные проверки: npm test, npm run test:ai и npm run test:bootstrap. npm run check:docs проверяет обе языковые версии после сборки. npm run test:release проверяет готовое приложение без модели, автономный HTML, PDF и снимки. Генераторы шрифтов и фирменных материалов вместе с requirements-assets.txt находятся только в Framework.

| Команда | Результат |
| --- | --- |
| `npm run typecheck` | Типы пакетов, приложений, сценариев и тестов |
| `npm run check:boundaries` | Запрещённые импорты между пакетами |
| `npm run check:ui` | Привязки токенов и отсутствие локальных визуальных переопределений контролов |
| `npm run build:ai` | Пакет генерации |
| `npm run build:editor` | Редактор и демонстрация |
| `npm run build:docs` | Справочник и руководства RU/EN |
| `npm run build:server` | Исполняемые файлы API и инициализации |
| `npm run build` | Полный выпуск в dist/site |
| `npm test` / `npm run test:ai` | Модульные проверки |
| `npm run test:browser` | Три браузера, отдельный тестовый сервер |
| `npm run test:docker` | Приёмка интерфейса уже работающего Docker-приложения в трёх браузерах |

Сборка читает JS/CSS и материалы из установленного пакета. Она не обращается к соседнему checkout Framework, не запускает его сборку и не скачивает модель. npm run test:compatibility проверяет единственную точную версию Framework в дереве зависимостей.

## Интерфейс и стили Framework

Требование FR-UI-01 распространяется на генерируемые сайты и презентации и на собственный интерфейс Constructor: редактор, галерею, корзину, библиотеки, историю, ИИ, диалоги, демо и обе локализации документации. Используйте публичные компоненты, классы и токены установленного Framework. Общие кнопки и диалоги создаются через `apps/editor/src/ui.ts`, поля — через `ui-fields.ts`.

Constructor задаёт расположение панелей, адаптивную компоновку и поведение предметных компонентов. Типографику, цвета, границы и состояния базовых контролов определяет Framework. Размер выбирается библиотечным вариантом; переопределять публичные `--af-*` и копировать визуальные рецепты в локальный CSS нельзя. Если нового варианта нет, используйте подходящие существующие компоненты либо сначала выпустите общее изменение в Framework.

`mountControls` подключает публичные Select и DatePicker к доверенным контролам, следит за добавлением и удалением полей и освобождает обработчики при закрытии. Списки с обновляемыми вариантами поддерживаются самим Framework; глобально отключать улучшение через `data-af-select-native` нельзя. Подписи полей используют `.af-label`, выбор — `.af-check` с `.af-checkbox`/`.af-radio`, карточки и счётчики — `.af-card`/`.af-badge`.

`npm run build` включает `check:ui`: проверяются CSS и классы в TS/HTML-разметке контролов. Сравнение с чистым CSS Framework и состояния контролов проверяются в `tests/ui-framework.spec.ts`; самостоятельный HTML продолжает использовать runtime и CSS Framework без стилей оболочки.

## Компоновка редактора

Шапка инспектора находится вне `.inspector-body`; прокручивается только содержимое. Отступы группы настроек задаёт один `.settings-group-body`, без общих правил вида `.property-group > div`. Панели команд используют штатный средний размер Framework, компактная шапка — `--sm`, нижние команды телефона — `--lg`.

Ручки выбранного блока доступны при узком контейнере и не зависят от hover. При изменении масштаба они сохраняют размер на экране и остаются внутри видимой области, с учётом нижних команд. Не скрывайте их правилами media/container query. Проверки геометрии, перекрытий и настоящего изменения размера находятся в `tests/editor-layout.spec.ts`; этот набор запускается и против Docker.

Общие шапки окон создаются через `dialogHeader`. Закрытие восстанавливает вызвавший контрол и после его пересоздания при применении. В подборе оформления прокручивается `.fit-body`; шапка и команды остаются отдельными частями окна. Кнопки не должны сжиматься до наложения текста.

Для библиотеки материалов, истории, проверки качества и хранилища используйте `libraryDialog`: заголовок находится вне `.library-dialog-body`, а команды хранилища — в отдельной `.library-dialog-actions`. Прокручивается только тело. Длинные названия и адреса переносятся внутри окна; карточки и строки списка могут увеличиваться по высоте. `tests/library-dialogs.spec.ts` проверяет окна от 320 px до широкого экрана и короткое окно 844×390, доступность закрытия после прокрутки, удаление и повторное открытие, восстановление с Undo, сохранение описания/фона и переход к проблемному блоку. Эти сценарии включены и в `test:docker`.

`dialogFrame` возвращает `{dialog, body}` для окон галереи: содержание добавляется в `body`, команды — отдельной нижней строкой. Кнопки отправки создания и переименования связаны с формой через штатный атрибут `form`, поэтому работают и при нажатии Enter. Переименование возвращает фокус к меню той же карточки по идентификатору проекта, в том числе после обновления галереи. Уведомления галереи очищаются после разрешённого перехода, чтобы старое действие «Отменить» не закрывало команды редактора. Выбор композиции и компоновки тоже использует `libraryDialog`; минимальная ширина их сетки ограничена шириной тела окна. `tests/project-dialogs.spec.ts` проверяет эти действия, отмену, ошибки названия, обе формы создания, применение/Undo и окна с увеличенными интервалами текста; набор включён в Docker-приёмку.

Окно ИИ переходит в одну колонку при ширине до 1023 px или высоте до 500 px. Панель применения следует после свойств и не накрывает их. Место презентации резервируется в формате 16:9 до первого ResizeObserver renderer. Свойства получают `current`, чтобы применяться к актуальному черновику; копирование также читает последнюю версию блока. Эти сценарии и возврат фокуса проверяет `tests/editor-dialogs.spec.ts` через публичный интерфейс, включая Docker; ответы модели в тестах имитируются.

Постоянный `#catalog` тоже отделяет шапку от `.library-dialog-body`; повторное открытие и переключение между блоками/секциями сохраняют штатный lifecycle контролов. `libraryDialog` делает прокручиваемое тело именованной областью с `tabindex=0`, чтобы объяснения без полей и кнопок можно было прокручивать с клавиатуры. Название в структуре использует отдельную форму с внешней кнопкой отправки и возвращает фокус к меню строки; запись меняет только рабочую подпись в настройках браузера. В конфликте сохранения все три команды находятся вне прокручиваемого тела, а ошибка записи объявляется через `role=alert` и допускает повтор. На время записи команды и закрытие недоступны. Имя отдельной копии резервирует место под суффикс « — копия» в пределах 200 символов. `tests/editor-recovery-dialogs.spec.ts` проверяет каталог/Undo, сохранение и сброс подписи, ошибки записи и работу двух настоящих вкладок, включая скачивание несохранённого документа, чтение последней записанной версии и прокрутку объяснения по Tab/Home/PageDown. Эти сценарии включены в Docker-приёмку.

Диагностика показа использует `libraryDialog`: закрытие остаётся в шапке, команды, отчёт и образцы прокручиваются в теле. Закрытие прерывает текущий запрос и возвращает фокус; повторное открытие создаёт независимую проверку. Контейнеры демообразцов добавляются на страницу до вызова рендера; область слайда заранее получает пропорции 16:9, чтобы изменение высоты не вызывало цикл ResizeObserver в WebKit. `tests/demo-diagnostics.spec.ts` проверяет узкое/короткое окно, увеличенные интервалы, axe, клавиатуру, два образца, отмену запроса и повтор после ошибки соединения или записи. API модели в этих браузерных тестах имитируется; реальная приёмка выполняется отдельно через `test:model`.

Публикация `bootstrap.json` сохраняет атомарную замену и кратко повторяет её при `EPERM`, `EACCES` или `EBUSY`: читатель или антивирус Windows может временно держать файл открытым. Остальные ошибки возвращаются сразу; число попыток ограничено шестью. Проверки временной блокировки и постоянного сбоя находятся в `tests/bootstrap.test.ts`.

Генерация передаёт тему секции отдельно от назначения плана: авторское назначение сохраняется в запросе как дополнение. `contentFormat` использует ссылку на целый исходный факт для короткого подходящего абзаца; общий факт для нескольких карточек не фиксирует их тексты одинаковым предложением. Явный список показателей после двоеточия задаёт значения и единицы, лишние слоты остаются пустыми. Проверки содержания рассматривают пояснения и карточки без заголовка секции, чтобы заголовок не скрывал уход от темы. Автоматические проверки являются эвристиками; оценка 20 исходных ответов выполняется отдельно.

`ai:acceptance` поддерживает `AF_BROWSER_CHANNEL`, `AF_TEST_URL`, `AF_AI_TEST_URL` и `AF_AI_REPORT_DIR`, сохраняет исходные запросы/схемы/ответы API и хеши реализации. Неполный прогон или техническая ошибка дают ненулевой код завершения. Этот сценарий вызывает общий генератор через dev-сервер; `test:model` отдельно проверяет собранный Docker через пользовательский интерфейс. `ai:report` использует тот же каталог, связывает `review.json` с `acceptance.json` по времени завершения и не объявляет порог 18/20 по неполному набору. Проверка отчёта: `npm run test:ai-report` (Python 3).

Передача содержания добавляет в контекст модели краткий контракт полей, приоритетные факты и требования к типу результата. `rankedFacts` учитывает действия редактора; новый план выравнивает исходную предпосылку по теме до авторского просмотра. При продолжении авторское назначение сохраняется. Новый неподтверждённый заголовок остаётся свободным; кавычки, просмотренный план и исправление скопированного имени материала фиксируют его.

`sourceEvidence` сохраняет исходные предложения и может добавить самостоятельные действия из однозначного утвердительного перечисления с известным исполнителем. Отрицания, условия и неподдерживаемый префикс отключают разбиение. Для карточек источник разделён на непересекающиеся группы допустимых ссылок; исходный текст сохраняется в запросе. `source-table` допускает ячейки только из коротких фактов одного свойства и соответствующего формата, без обрезки и выдуманных значений. Выход переводится в прежние команды/Document schema 3. Повтор целого абзаца между секциями вызывает одну попытку исправления; израсходованный исходный абзац остаётся доступным для перефразирования.

`AF_AI_CASES=1,2` запускает явно помеченный отладочный поднабор; он не засчитывается как 20 заданий. `AF_AI_TASKS_FILE` задаёт другой набор с `label`, `sources`, `cases` и необязательным `count`. Пример контрольного набора и критерии сохранены в `artifacts/ai-instructions-2026-10-26/holdout-input.json`. По умолчанию сценарий сам управляет временным dev-сервером, чтобы завершение внешнего сервера не обрывало приёмку. HTML-отчёт выводит контрольную выборку отдельно от порога 18/20.

## Новый элемент или композиция

Опишите элемент в схеме и общем renderer, затем добавьте настройки редактора и пример в документации. Для композиции задайте семантические места, допустимые компоненты, варианты сетки и ограничения текста. Проверяйте сохранение идентификаторов, смену компоновки, экспорт и мобильный порядок. API не должен зависеть от внутренних файлов редактора.

Новый провайдер реализует AIProvider. Он возвращает данные по переданной схеме и уважает AbortSignal. Отдельно проверяются неверный JSON, таймаут, отмена и недоступность сервиса. Измерение и оформление остаются кодом конструктора.

## Работа через PR

Одна задача — одна небольшая ветка. В PR укажите проблему, итоговое поведение, совместимость и результаты проверок. Для визуального изменения приложите снимки; для схемы — тест старого документа; для API — отрицательные сценарии. Изменение общей библиотеки требует проверки потребителей. Документация обновляется сразу на RU и EN.

Изменения веток не должны включать модели, локальные проекты, секреты и полный каталог тестовых артефактов. Владельцы областей назначаются командой после создания репозитория; до этого конкретные GitHub-пользователи не выдумываются.

## Обновление Framework

Обновляйте корневой package.json, apps/editor/package.json и packages/ai/package.json одной точной версией и фиксируйте package-lock.json. scripts/select-framework-version.mjs принимает версию или --minimum для проверки совместимости. Изменения схемы/renderer сначала выпускаются в Framework, затем принимаются отдельным PR в Constructor. Локальный npm link, file:, Git URL и alias на исходники запрещены. configure-registry.mjs меняет адрес архива, сохраняя версию и integrity.

Dependabot проверяет пакет ежедневно в 09:00 Europe/Moscow. Укажите реальный HTTPS registry в .github/dependabot.yml и read token отдельно в Actions/Dependabot secrets. Автоматическое слияние и deploy от релиза Framework не включены.

Отчёт scripts/validation-report.py использует необязательный PyMuPDF: python -m pip install -r scripts/requirements-reports.txt.

## Адаптивные размеры и доступность

Constructor закрепляет Framework 1.2.0 во всех workspaces и lockfile. `widget.responsive.tablet/mobile` — публичный контракт библиотеки; исходники Framework не копируются в приложение. `editor-responsive.spec.ts` проверяет независимые размеры, ошибки формы, смену экрана, отмену, сохранение, повторное открытие и автономный HTML. Встроенный Chrome zoom проверяется отдельным нативным прогоном: CSS zoom холста и уменьшенный viewport не заменяют эту проверку. NVDA проверяется как настоящий процесс Windows с журналом озвучивания. Сенсорная эмуляция не подтверждает физический телефон и экранную клавиатуру.
