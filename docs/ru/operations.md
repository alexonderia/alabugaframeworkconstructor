# Docker и эксплуатация

## Версии образов и откат

Перед сборкой выпуска задайте в `.env` значения `AF_WEB_IMAGE=alabuga-web:release-001` и `AF_API_IMAGE=alabuga-api:release-001`. Выполните `docker compose -f compose.yaml -f compose.build.yaml build web api` и сохраняйте образы до приёмки следующего выпуска. Для отката верните прежние теги и выполните `docker compose up -d --no-build web api`. Не пересобирайте старые теги из новых исходников; сохраняйте порт, origin и тома. Перед повторным запуском инициализации остановите текущую загрузку, чтобы два процесса не писали состояние одновременно.

## Варианты запуска

`docker compose -f compose.yaml -f compose.build.yaml up --build -d` запускает собранное приложение и лёгкий API без модели. Адрес — `http://127.0.0.1:4176/demo/`. `docker compose -f compose.yaml -f compose.build.yaml --profile ai up --build -d` добавляет Ollama и одноразовую инициализацию. Docker и драйверы GPU устанавливаются оператором; приложение не устанавливает их самостоятельно.

Для изменения исходников с автоматическим обновлением: `docker compose -f compose.dev.yaml up --build`. Зависимости находятся в отдельном томе, чтобы не смешивать Windows- и Linux-node_modules. При изменении lock-файла контейнер выполняет npm ci заново при перезапуске.

## Первый запуск ИИ

Сначала Docker загружает образ Ollama. Инициализатор ожидает сервис, сверяет версию, ищет модель `qwen3.5:2b` и её digest в config/model-lock.json. При отсутствии весов запускается загрузка с отображением состояния. После загрузки digest проверяется повторно. Несовпадение блокирует ИИ; существующая модель не заменяется автоматически.

Текущий тег реестра отличается от ранее принятой текстовой сборки Q8_0. Для точного воспроизведения в `config/pinned-model-manifest.json` сохранён её исходный манифест. Инициализатор скачивает четыре файла официального реестра по хешам и проверяет размер и SHA-256 каждого файла до публикации манифеста. Незавершённые файлы докачиваются через HTTP Range. Веса не входят в Git или образы приложения. Не заменяйте эту процедуру непроверенной командой `ollama pull qwen3.5:2b`. При наличии конфликтующей модели сначала проверьте и сохраните её; удаление её тега — явное действие оператора, инициализатор его не выполняет. Только инициализатор работает от root для записи общего тома Ollama; API работает от непривилегированного пользователя node.

Том `ollama-models` сохраняет веса между перезапусками. Не выполняйте `docker compose down -v`, если намерены сохранить модель. Без интернета работает уже подготовленная установка с локальными образами. Холодный запуск без образов или весов требует сети.

## Проверка и восстановление

```sh
docker compose ps
docker compose logs --tail=100 api
docker compose --profile ai logs --tail=100 model-init
docker compose --profile ai run --rm model-init
```

Последняя команда повторяет подготовку после обрыва загрузки. Health API подтверждает жизнь процесса; readiness отдельно сообщает о модели и подготовке. При ошибке digest остановите выпуск, сопоставьте закреплённую конфигурацию с ожидаемой моделью и проведите повторную приёмку. Не меняйте lock-файл только для подавления ошибки.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| AF_OLLAMA_URL | Адрес Ollama; в Compose — http://ollama:11434 |
| AF_AI_HOST / AF_AI_PORT | Интерфейс и порт API; нативно 127.0.0.1:4176 |
| AF_AI_CONTEXT | 4096; для повторного измерения памяти разрешено 2048 |
| AF_AI_ENFORCE_LOCK | Проверка включена по умолчанию; 0 допустим только для тестового сервиса, не для приёмки |
| AF_AI_STATE_DIR | Том состояния первоначальной загрузки |
| AF_ALLOWED_ORIGINS | Разрешённые адреса интерфейса через запятую |
| AF_AI_PROXY | Адрес API для Vite |

Для нативной Ollama укажите доступный из контейнера AF_OLLAMA_URL. `host.docker.internal` — адрес хоста, но сервис, слушающий только host loopback, может быть недоступен из Docker. Не публикуйте Ollama в интернет для обхода этого ограничения; настройте доступ во внутренней сети либо запускайте редактор/API нативно.

## GPU и обновление

GPU-профиль требует NVIDIA Container Toolkit на Linux либо совместимой настройки Docker Desktop/WSL2. Полное размещение весов проверяется через Ollama, а общая видеопамять — отдельно. Windows/Vulkan и Linux-контейнеры имеют разные условия; 4 ГБ не объявляются достаточными без измерения текущего запуска.

Перед обновлением скачайте переносимые проекты. Соберите новый образ, проверьте health/readiness, оба формата и экспорт. Для отката используйте предыдущую версию образа и совместимые проекты; не удаляйте том модели. Версия схемы в этом выпуске не меняется. Логи не должны включать полные пользовательские запросы и документы.

## Независимые образы и реестр

Для сборки задайте ALABUGA_NPM_REGISTRY и ALABUGA_NPMRC_FILE по .env.example. npmrc передаётся как BuildKit secret и не попадает в слой образа. Готовые образы запускаются через compose.yaml без реестра и npm-учётных данных; compose.build.yaml используется только для сборки. API и web выпускаются согласованной парой с версией, commit SHA и digest. Развёртывание использует эту пару без пересборки на сервере; при неуспешном healthcheck сценарий deploy возвращает предыдущую пару. Проверка production-отката ещё требуется.

VITE_FRAMEWORK_DOCS_URL задаёт URL независимого справочника до сборки web. В Actions это repository variable FRAMEWORK_DOCS_URL. Локально интерактивный справочник находится на 4391, приложение для проверки разделения — на 4390. Эти тестовые адреса не заменяют origin 4176 пользовательской установки.

ALABUGA_NPM_REGISTRY и read/publisher secrets, HTTPS-сервер реестра, отдельные backup/restore и мониторинг настраиваются по Framework infra/registry/README.md. JWT действует 30 дней; обновляйте секреты до 25-го дня. Секрет публикации не передаётся Constructor. Событие выпуска Framework не запускает deploy приложения.
