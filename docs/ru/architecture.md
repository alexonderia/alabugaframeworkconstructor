# Архитектура

Constructor использует Framework {{FRAMEWORK_VERSION}}; минимальная поддерживаемая версия — {{FRAMEWORK_MINIMUM}}. Эти значения подставляются из package.json при сборке руководства. Компоненты интерфейса инициализируются только в принадлежащих редактору контейнерах с cleanup перед заменой DOM. DatePicker использует enhanced-компонент; Select сохраняет связь с нативным полем и использует публичный компонент Framework. Editable-холст не проходит общую инициализацию компонентов.

`document-surface.ts` создаёт iframe с публичными standalone CSS/JS Framework. Тот же runtime используется автономным HTML и общей проверкой качества; код renderer в Constructor не копируется. Изоляция предназначена для размеров и маршрутизации документа; iframe содержит доверенный runtime и прошедший валидацию AFDocument. Preflight проверяет реальные viewport сайта 1440/768/390 px и слайды 1600 px и блокирует экспорт при переполнении или недоступном изображении.

В IndexedDB 3 внутренний счётчик Project.version защищает атомарные записи от устаревшей вкладки. BroadcastChannel уведомляет интерфейс, но проверка версии выполняется в транзакции. История индексирована по проекту; повторяющиеся материалы читаются пакетом. Кэш материалов ограничен 16 МиБ приблизительного объёма строк UTF-16. Очередь сохранения оставляет активную запись и последний ожидающий snapshot. Очистка материалов проверяет ссылки проектов, корзины, истории и ИИ-черновика под одной транзакцией; счётчик версии и служебные подписи структуры не входят в AFDocument.

## Границы пакетов

| Пакет | Ответственность | Зависимости |
| --- | --- | --- |
| framework | Схема, runtime, композиции, оформление, экспорт | Zod; без редактора |
| ai | Контракты, команды, генерация и проверки содержания | Публичные API framework, Zod |
| editor | Витрина, холст, свойства, IndexedDB, интерфейс ИИ | framework, ai |
| ai-server | HTTP, ограничения, Ollama, инициализация модели | Node.js, конфигурация модели |
| docs | Руководства Constructor и примеры из установленного пакета | framework |

Framework находится в отдельном репозитории и публикует @alabuga/framework. Constructor использует точную версию {{FRAMEWORK_VERSION}} и собственный lock-файл. Внутренние editor, ai и ai-server остаются приватными workspaces приложения. Изменение библиотеки выпускается отдельно; приложение принимает его собственным PR. Переходы между пакетами разрешены только через публичные exports. Конфигурация модели остаётся в Constructor.

`npm run check:boundaries` проверяет эту матрицу: editor может зависеть от публичных exports ai, а ai и ai-server не импортируют другие workspaces приложения. Относительные переходы между workspaces запрещены; editor и ai не используют встроенные Node.js-модули. Модель и операции над документом (`model`, `sections`, `section-name`, `document-content`, `property-patch`, `editor-save`, `editor-session`) могут импортировать только друг друга и публичные schema/compositions Framework; UI и IndexedDB в их зависимости не входят. Список модулей и правила находятся в `scripts/import-boundaries.mjs` и должны обновляться при выделении новых модулей.

Проверка также ищет циклы в графе относительных импортов исходников workspaces, включая типовые импорты, реэкспорты и динамические импорты с буквальным путём. Вычисляемые пути и runtime-зависимости этим графом не покрываются. Отрицательные сценарии и запуск команды на изолированном тестовом workspace входят в `npm test`.

## Сессия редактора

`editor-session.ts` владеет `EditorModel`, идентификатором проекта, подтверждённой версией записи, `EditorSaveQueue` и `AbortSignal`. Изменения, undo/redo, смена проекта, создание копии при конфликте, загрузка сохранённой версии и применение готового документа проходят через сессию. Чтение, запись, история и уведомления передаются через `SessionServices`; модуль не импортирует DOM, UI или IndexedDB.

`main.ts` связывает сессию с хранилищем и контроллерами представления, задаёт команды, выбранный блок, текущую секцию и переходы. `save-conflict.ts` отвечает только за окно выбора действия и фокус. Выход из редактора проверяет незавершённые формы, ждёт очередь и создаёт точку восстановления. Завершение сессии отменяет обработчики и уведомления; уже поставленные в очередь снимки дописываются. Ответ чтения или применения, пришедший после смены проекта или завершения сессии, не подменяет текущий документ. Создание нового проекта ждёт записи и истории предыдущего; ошибка сохраняет текущую сессию.

`editor-canvas.ts` владеет Framework-контроллером, подписью отрисованного документа, inline-привязками, инструментами и ручками блоков, подсказкой переполнения и восстановлением позиции прокрутки. `synchronize` обновляет данные рендерера без повторной отрисовки текста во время ввода. `editor-inspector.ts` владеет черновиком формы, состояниями проверки, настройками секции/документа, обновлением после inline-ввода, фокусом и адаптивной панелью. При частичном обновлении инспектора незавершённые поля сетки не перезаполняются. Изменения передаются callbacks в сессию; инспектор не вызывает холст напрямую.

Оба контроллера получают сигнал сессии и освобождают собственные обработчики, observer-ы, таймеры, animation frames и контролы. Повторное завершение безопасно. Проверка импортов запрещает им напрямую импортировать `main`, `editor-session`, `storage` или друг друга; существующие вложенные формы и библиотека материалов сохраняют свои зависимости. Формат данных и видимые поля не меняются.

## Документ и отображение

Название секции (`page.title`) служит метаданными структуры. Перед отрисовкой адаптер создаёт представление документа с пустыми названиями секций; содержимое видимых элементов не меняется. Это представление используют холст, миниатюры, предпросмотр, проверка качества и HTML-экспорт. Модель, сохранение, `getDocument()` адаптера и переносимый JSON сохраняют исходные названия; подбор оформления слайда также возвращает его исходное название.

Поддерживаются схемы документа 1–5. Документы схем 1–3 без новых параметров нормализуются в 3; отдельные адаптивные размеры используют схему 4, настройки подписи и номера слайда — схему 5. Версия переносимого файла проекта и версия IndexedDB остаются 3; это независимые номера. В документе хранятся секции, элементы, позиции, фон, типографика, действия и анимации. Runtime одинаков для холста, предпросмотра и экспорта. Редактор добавляет управление поверх результата и хранит историю изменений в EditorModel. Импорт схемы не требует DOM или CSS; измерение слайда и отображение требуют браузера.

## Материалы и экспорт

`storage.ts` сохраняет прежние 35 публичных имён и переэкспортирует операции из `storage/`. `db.ts` владеет единственным ленивым подключением, миграциями и координатором транзакций; `projects`, `revisions`, `drafts` и `settings` содержат соответствующие операции. `assets` отвечает за подготовку, хеширование, кэш и загрузку материалов, `images` — за обход ссылок, `maintenance` — за проверку использования и очистку, `legacy-import` — за старый localStorage. `types` содержит записи и построение summary; `project-state` — версии, уведомления и ошибку конфликта. Проверка импортов ограничивает направления между этими модулями и запрещает обращение обратно к фасаду, интерфейсу или сессии.

Запись проекта по-прежнему использует одну транзакцию над projects/summaries/assets/settings; очистка повторно проверяет ссылки под блокировкой projects/revisions/settings/assets. Подготовка изображений выполняется до открытия транзакции. Синхронное исключение в её callback теперь вызывает `abort`, поэтому изображение не остаётся без описания при ошибке следующей записи. Имя БД, stores, версия 3 и алгоритмы миграций не изменены.

`project-file/format.ts` отдельно разбирает переносимые файлы и не зависит от IndexedDB или UI; `document-validation.ts` содержит общую проверку документа для этих операций. Эти два модуля защищены правилами чистых операций над документом. `storage/portable-project.ts` собирает переносимый файл после разрешения материалов. `framework-assets.ts` использует публичный API подготовки изображений без импорта renderer; Framework-адаптер сохраняет прежние переэкспорты этих функций.

IndexedDB хранит изображения отдельно от структуры документа; ссылки используют `asset:` и устойчивый идентификатор. Адаптер редактора разрешает их перед отображением и экспортом. Библиотечный экспорт также принимает асинхронный `resolveAsset(id)` и явные CSS/JS автономного runtime. Он не обращается к IndexedDB.

Обработка изображений находится в framework; хранилище не импортирует редакторский экспорт. Автономный runtime уже собран в установленном npm-пакете и читается через публичные standalone.css и standalone.js. Constructor не собирает библиотеку. CSS, шрифты и сценарий встраиваются в итоговый HTML.

## Генерация

Запрос → структура → заполнение смысловых мест → команды → изолированный черновик → проверки → применение. AIProvider отделяет транспорт от генерации. GenerationServices передаёт браузерный подбор оформления; сам пакет ai не импортирует UI редактора. Проверка геометрии передаётся callback-функцией.

ИИ-панель загружается динамически. Изменения черновика не заменяют текущий проект до применения. Схема проекта не содержит запросы, состояния генерации или служебные отчёты.

## Решения и ограничения

Нет серверной базы проектов, аккаунтов и синхронизации. Docker volume модели не является резервной копией проектов. Сервер ИИ обрабатывает один запрос одновременно. Изменение этих правил требует отдельного архитектурного решения и миграционных тестов, а не скрытого расширения текущего рефакторинга.

## Адаптер и независимые сайты

apps/editor/src/framework-adapter.ts объединяет renderer, подбор оформления, адрес встроенных материалов и DOM-опоры inline-редактирования. Библиотека не импортирует IndexedDB, AI или сервер. Совместимость DOM, CSS и API описана в Framework docs/public-contract.md; нарушение этого контракта требует major-версии библиотеки.

Интерактивный справочник Framework — отдельный статический сайт. Руководства Constructor и /api/ai/ остаются на origin приложения. VITE_FRAMEWORK_DOCS_URL задаёт переход к Framework, CONSTRUCTOR_URL в сборке его документации — обратные ссылки. Изменение репозитория не меняет origin или структуру пользовательской БД.
