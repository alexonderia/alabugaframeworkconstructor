## Воспроизводимая карта

| Runtime Compose | После вынесения build runtime-настройки сервисов и volumes совпадают с исходными |

Автоматически защищены от непредусмотренного изменения: конфигурации модели, исходники AI и ai-server, коллекции public/projects, фирменные материалы, WOFF2/LFS-оригиналы, snapshot Figma-токенов, закреплённая Node-версия, .editorconfig/.gitattributes и сценарии подготовки/запуска модели. Для бинарных материалов используются точные байты/хеши; для текстов допустима нормализация LF/CRLF. LFS сравнивает содержимое с OID исходного pointer, а не с текстом pointer-файла.

Повторная проверка из Constructor:

```sh
node scripts/audit-split.mjs --framework-root ../alabuga-framework --output docs/split-file-audit.json --with-compose
```

Это отдельный инструмент проверки двух checkout. Обычные npm ci, build, test и документация ни одного проекта не требуют checkout второго. При отсутствии Docker уберите --with-compose; тогда сравнение runtime-конфигурации явно отмечается как невыполненное.

## Границы доказательства

21 октября дополнительно завершено [сравнение готовых сборок 4176 и 4390](parity-4176-4390.ru.md). Восстановлены вход через справочник и четыре прежних адреса примеров с сохранением query/hash. Полный набор Constructor после этого прошёл 78 браузерных сценариев; вместе с 15 ранее проверенными сценариями Framework — 93. Реальные действия в обеих Docker-сборках, переносимые документы/материалы, автономный HTML и PDF совпали по проверяемым контрактам. Повторный обход 40 страниц и 73 URL также успешен. ИИ недоступен в обеих сборках с одинаковым таймаутом.

Исходный коммит не содержит .env с секретами, скачанные веса моделей, Docker volumes или браузерную IndexedDB. Их побайтовую сохранность нельзя доказать сравнением с Git; они этой работой не переносились и не удалялись. Тесты проверяют протоколы сохранения/миграции на изолированных данных, а не являются резервной копией пользовательского браузера.

Firefox/WebKit, реальная GPU-приёмка после разделения, production HTTPS/backup/restore, GitHub push и облачные workflows остаются отдельными невыполненными этапами. Сверка файлов не выдаётся за завершение production-перехода. Изменения документации/проверки пока находятся в рабочих деревьях обоих репозиториев.
