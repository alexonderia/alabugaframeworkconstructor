ИИ пока одинаково не готов на обоих адресах. Подробности: [сравнение сборок](parity-4176-4390.ru.md).

1. Создать приватный alexonderia/alabuga-framework и авторизовать Git CLI; отправить main и теги. Constructor остаётся в текущем репозитории.
2. Указать домен HTTPS-реестра, DNS и SSH-сервер. Развернуть отдельный registry stack, production publisher/read accounts, сертификат, renewal timer и зашифрованные off-server backups.
3. Настроить ALABUGA_NPM_REGISTRY и секреты Actions/Dependabot по README реестра. После первой production-публикации запустить configure-registry.mjs с реальным URL: он переносит адрес архива, сохраняя версию и integrity. Используется тот же проверенный архив либо воспроизводимая Linux CI-сборка.
4. Выполнить облачную матрицу браузеров и ручную GPU-приёмку, затем независимый Constructor release/deploy. Deploy получает пару образов по digest из release asset, сохраняет прежнюю пару и возвращает её при неуспешном healthcheck.
5. Подтвердить production backup/restore и Dependabot с реальным endpoint. До этого инфраструктурные критерии production остаются открытыми.

Локальные исходники, конфигурации и проверки выполнены. Внешняя GitHub-публикация и production-развёртывание ожидают доступа и параметров среды.
