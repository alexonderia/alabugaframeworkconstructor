# Сравнение сборок на 4176 и 4390 — 21 октября 2026

Проверены две работающие Docker-сборки через установленный Chrome: исходный монорепозиторий на http://127.0.0.1:4176/ и Constructor 0.7.0 с опубликованным Framework 1.0.2 на http://127.0.0.1:4390/. Найденные расхождения входных маршрутов исправлены, web-образ Constructor пересобран и запущен. Исходный образ на 4176 не заменялся.

## Что исправлено

| Маршрут | До исправления на 4390 | Теперь |
| --- | --- | --- |
| `/`, `/index.html` | Переход в demo вместо справочника | Открывается интерактивная документация Framework, как при входе на 4176 |
| `/demos/panel.html`, `/demos/form.html`, `/demos/slides.html`, `/demos/showcase.html` | 404 | Открываются соответствующие работающие примеры Framework |
| «Помощь» → «Документация» в проектах | Прежняя ссылка попадала на неправильную страницу | Новая вкладка с полным руководством `/docs/ru/projects.html` |

Framework имеет самостоятельный сайт http://127.0.0.1:4391/. Поэтому входные маршруты справочника и примеров на 4390 перенаправляют туда, сохраняя query-параметры и hash. Целевой адрес задаётся `VITE_FRAMEWORK_DOCS_URL` при сборке. В Constructor находятся только страницы перехода; копии исходников Framework не добавлялись. `/demo/`, `/builder/`, `/api/ai/` и прикладные руководства `/docs/{ru,en}/` остаются на 4390. Обратные ссылки справочника возвращают в Constructor.

## Автоматические проверки и артефакты

После изменения маршрутов полный набор Constructor прошёл **78/78** Chromium-сценариев через Chrome на Node.js 24.19.0/npm 11.17.0. В него входят три новых проверки в `tests/navigation.spec.ts`: корень и закладки, четыре прежних примера, документация из диалога помощи. Они работают без checkout или запущенного сервера Framework: внешний сайт в этих трёх тестах заменён ответом теста. Сравнение реальных Docker-сборок и обход документации, описанные выше, выполнены отдельно без этой замены.

С учётом ранее выполненных 15 браузерных проверок Framework подтверждены 93 сценария Chrome. Ранее выполненные 62 модульные проверки не изменялись этим исправлением маршрутов. `check:docs` и `git diff --check` успешны.

Повторная [сверка файлов и настроек](split-file-audit.json) после исправлений успешна: 302 исходных файла, 353 назначения, все 145 прежних тестовых сценариев сохранены (текущий набор — 155), 6 LFS-оригиналов, 22 exports, 124 эффективных токена, 6 прежних значений `.env.example` и runtime Compose. Ошибок и неучтённых исходных файлов — 0.

Локальные результаты находятся в игнорируемом `artifacts/split/`:

- `production-parity/report.json` — успешное сравнение обеих сборок, документов и ответов API;

Постоянная регрессия маршрутов запускается из репозитория командой `npm run test:browser -- tests/navigation.spec.ts` (`AF_BROWSER_CHANNEL=chrome` для установленного Chrome).

## Ограничения

ИИ одинаково недоступен на обоих адресах: `/api/ai/health` возвращает 200, readiness — `ready: false` с таймаутом, status — 503 с тем же таймаутом. Некорректный запрос генерации отклоняется с 400 на обеих сборках. Реальная генерация и GPU-приёмка не подтверждены; равенство ответов не означает исправность модели.

Браузерные проверки использовали изолированные контексты с тестовыми проектами. Порты 4176 и 4390 образуют разные origin и имеют раздельные IndexedDB. Пользовательские проекты между ними не переносились; для ручного переноса предназначен JSON с материалами. Firefox/WebKit и внешняя production-инфраструктура этим сравнением не проверялись.
