# Работа с проектом

[English](CONTRIBUTING.en.md)

1. Создайте ветку для одной задачи. Не меняйте формат документов вместе с механическим переносом кода.
2. Пользуйтесь публичными exports пакетов. Новую зависимость внесите в пакет-потребитель и обновите общий lock-файл.
3. Сохраняйте существующие адреса, идентификаторы, действия, отмену и пользовательские данные. Ошибка записи не должна сопровождаться сообщением «Сохранено».
4. Запустите модульные проверки, типы, проверку границ и сборку. Для изменений renderer, схемы или хранения требуется полная браузерная регрессия.
5. Обновите соответствующие страницы RU/EN. Добавьте пример использования и отрицательный сценарий для нового публичного API.
6. В PR опишите проблему, итоговое поведение, совместимость и ограничения доказательств. Не выдавайте имитацию модели за реальную генерацию.

## Перед первым push

Назначьте приватную организацию и имя репозитория, включите Git LFS, обязательное ревью и проверки Quality. Запретите прямой push в main и назначьте реальные команды в CODEOWNERS. Проверьте staged-файлы на секреты и большие артефакты. Constructor не публикует свои workspaces. Framework выпускается отдельным пакетом и обновляется точной версией и lock-файлом.

## Доверенный GPU runner

Ручной workflow запускается только из main на runner с меткой `alabuga-gpu`. Настройте защищённое окружение `gpu-acceptance` с подтверждением команды. На машине должны быть Ollama, закреплённая модель и GPU. Не запускайте непроверенные PR на self-hosted runner. Скрипт приёмки поднимает собственный API на 4386 и завершает только этот процесс.

## Исходные материалы

Не изменяйте оригинальные PPTX/Figma в задаче рефакторинга. Производные материалы регенерируются отдельными сценариями и проверяются визуально. Для извлечения нужны Python, Pillow и fontTools; обычный разработчик использует подготовленные ресурсы. Не добавляйте открытую лицензию корпоративным материалам без отдельного решения владельца.

## После разделения

Настройте scoped registry и read token для npm ci. Изменение Framework принимается отдельным PR; исходники библиотеки не копируются в приложение. Подробности и прежние протоколы находятся в docs/ru/{development,ai,projects,quality,operations}.md. Python-отчёты: scripts/requirements-reports.txt; оригинальные шрифты, PPTX/Figma и генераторы материалов принадлежат Framework. Не меняйте origin при выпуске: IndexedDB остаётся в прежнем браузерном профиле.
